视频生成任务提交后，通过 `task_id` 轮询查询任务状态与生成结果。**SD2 推荐路径**：`GET /v1/video/generations/{task_id}`。若提交响应丢失，可用创建时响应头中的 `X-Oneapi-Request-Id` 做 [按 request_id 找回](#lookup-by-request-id)。

<Note>
  两种查询路径返回结构不同，请与提交路径保持一致：
  - **`GET /v1/video/generations/{task_id}`**（SD2 主路径）→ `{code, data: TaskDto}`，`status` 为大写（如 `IN_PROGRESS`、`SUCCESS`），视频地址在 `data.result_url`，上游原始 JSON（含 `usage`）在 `data.data`
  - **`GET /v1/videos/{task_id}`**（OpenAI 兼容）→ 扁平 `{id, object, status, progress, metadata.url}`，`status` 为小写（如 `in_progress`、`completed`）
</Note>

<RequestExample>
```bash SD2 主路径
curl https://gogogotoken.com/v1/video/generations/task_1234567890 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```bash 按 request_id 找回
curl "https://gogogotoken.com/v1/video/generations?request_id=YOUR_X_ONEAPI_REQUEST_ID" \
  -H "Authorization: Bearer YOUR_API_KEY"
```
</RequestExample>

## 路径参数

<ParamField path="task_id" type="string" required>
  视频生成任务 ID（提交响应中的 `id` / `task_id`）。
</ParamField>

## 请求头

<ParamField header="Authorization" type="string" required>
  API Key 鉴权信息，格式为 `Bearer YOUR_API_KEY`。
</ParamField>

## 按 request_id 找回任务 {#lookup-by-request-id}

提交接口超时、客户端未读到 body，但服务端可能已创建成功时：

```
GET /v1/video/generations?request_id=<X-Oneapi-Request-Id>
```

| 项 | 说明 |
|---|---|
| `request_id` | 必填。取自**首次创建**响应头 `X-Oneapi-Request-Id` |
| 有效期 | 约 **24 小时** |
| 权限 | 仅能查到**当前 API Key 所属用户**自己的任务 |
| 成功响应 | 与幂等重放相同形态的 OpenAI Video 任务对象（含 `id` / `task_id`）；响应头可能含 `X-Idempotency-Replayed: true` |
| 未找到 | HTTP **404**，`task_not_found`（过期、未落库，或无 task_id 的失败创建） |

<Tip>
  生产集成优先在提交时带 [`Idempotency-Key`](/video-generations#idempotency)，用同一业务键重试即可拿回原任务；`request_id` 找回适合「没带幂等键、但保存了响应头」的补救路径。
</Tip>

<ParamField query="request_id" type="string">
  网关请求 ID。与路径参数 `task_id` 二选一场景使用：本接口为查询串形式，无 path 中的 task_id。
</ParamField>

## 响应体（`/v1/video/generations/{task_id}`）

<ResponseField name="data.status" type="string">
  任务状态：`QUEUED`、`IN_PROGRESS`、`SUCCESS`、`FAILURE` 等。
</ResponseField>

<ResponseField name="data.progress" type="string">
  进度百分比字符串，如 `"50%"`。
</ResponseField>

<ResponseField name="data.result_url" type="string">
  生成成功后的视频 URL（平台提取自上游响应）。
</ResponseField>

<ResponseField name="data.upstream_task_id" type="string">
  上游火山方舟原始任务 ID（`cgt-...`），可用于官方控制台核对。早期创建的任务无此字段时缺省。
</ResponseField>

<ResponseField name="data.billing" type="object">
  本任务结算快照：结算状态（`pending` / `settled` / `refunded`）、最终扣费额度 `quota` 与金额 `amount`、计费 token 数 `billable_tokens`，以及提交时锁定的价格参数（`model_ratio` / `group_ratio` / `variant_ratio` / `promo_ratio` / `input_mode` 等）。金额与单价为十进制字符串；复算口径见 [计费说明](/billing#task-billing)。
</ResponseField>

<ResponseField name="data.data" type="object">
  上游任务查询的完整原始响应：实际模型版本 `model`、实际生成规格（`resolution` / `ratio` / `duration` / `framespersecond` / `seed` / `generate_audio` / `service_tier`）、完整 `usage` 等。请求 `duration=-1`（智能时长）时，此处的 `duration` 为官方最终选择的实际输出时长。
</ResponseField>

<ResponseField name="data.data.usage.completion_tokens" type="integer">
  Token 计费模型（`doubao-seedance-2-0` / `-fast`）的上游真实输出 token。结算口径以 `data.billing.billable_tokens` 为准（取自 `usage.total_tokens`，两者在 Seedance 任务中恒等）。
</ResponseField>

<Note>
  `data.data` 的完整度依赖后台轮询刷新：提交后立刻查询时 `data` 内仅有上游任务 ID，进入终态（`SUCCESS` / `FAILURE`）前请等待一轮刷新（约 15 秒）。
</Note>

## 轮询建议

状态通常按以下顺序变化：

```text
QUEUED / IN_PROGRESS -> SUCCESS / FAILURE
```

成功后的 `result_url` 约 24 小时内有效，请及时 [下载](/video-tools)。

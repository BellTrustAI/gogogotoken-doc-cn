所有 API 请求均通过 Bearer Token 鉴权。

## Base URL

| 环境 | 地址 |
| --- | --- |
| 生产 | `https://gogogotoken.com` |

## 请求头

```http
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

## 获取 API Key

1. 注册并登录 [gogogotoken.com](https://gogogotoken.com)
2. 进入控制台的 API Keys 页面
3. 创建 Key，按需设置**分组**、模型限制与配额

### 常用令牌分组（对话）

| 分组 | 用途 |
| --- | --- |
| `LLM - Kimi` | Kimi：`kimi-k2.5` / `kimi-k2.6` / `kimi-k2.7-code` / `kimi-k3` |
| `LLM - GLM` | 智谱：`glm-5.1` / `glm-5.2` |
| `LLM - DeepSeek` | DeepSeek：`deepseek-v4-pro` |

调用某模型时，API Key 所属分组必须已开通该模型。详见 [通用大模型](/llm-models)。

豆包 Seed 对话、Seedance / Kling 视频等使用各自对应分组，与上表相互独立。

## 用 Key 查询当前分组与可用模型 {#list-models}

`GET /v1/models` 会按**当前 API Key** 返回可用模型列表，并附带令牌元数据，便于适配器识别「这把 Key 落在哪个组」：

```bash
curl https://gogogotoken.com/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "success": true,
  "object": "list",
  "token_name": "控制台中的令牌名称",
  "group": "令牌分组名",
  "group_description": "用户可用分组中的描述文案",
  "groups": ["令牌分组名"],
  "data": [
    { "id": "doubao-seedance-2-5", "object": "model", "owned_by": "..." }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `token_name` | 控制台里该令牌的名称 |
| `group` | 当前生效分组；令牌为 `auto` 时值为 `"auto"` |
| `group_description` | 分组描述（取自后台「用户可用分组」；未配置则回落为组名） |
| `groups` | 本次列表实际展开的分组；固定组通常只有一项，`auto` 可能多项 |
| `group_descriptions` | 仅 `auto` 时出现：各组名 → 描述 |
| `data` | 该 Key 在生效分组下可用、且已配置计费的模型（若令牌开了模型白名单，则只含白名单内模型） |

<Tip>
  Seedance / GPT Image 等多档位令牌可用此接口确认分组与模型清单，无需再维护多套本地配置。
</Tip>

<Warning>
  请妥善保管 API Key，不要提交到公开仓库、前端代码或日志系统中。
</Warning>

视频生成是异步任务。提交后接口会立即返回 `task_id`，可以通过 [任务查询](/video-tasks) 轮询获取结果，也可以传入 `callback_url` 由上游主动推送结果（免轮询，见下文「回调通知」）。

<Note>
  本文档即 **Seedance 官方用法**（2.0 / 2.5）。`prompt`、`seconds`、`images`、`metadata.*` 等字段由平台转换为 ARK 上游请求体。模型价目与能力差异见 [视频模型列表](/video-models)。
</Note>

<Tip>
  **超时重试 / 响应丢失**：提交时建议带 `Idempotency-Key`（见下文）；也可保存响应头 `X-Oneapi-Request-Id`，用 [按 request_id 找回](/video-tasks#lookup-by-request-id) 查回 `task_id`。二者均约 **24 小时**有效，且不会重复预扣。
</Tip>

## 接口说明

<Note>
  通常需要 30-120 秒生成完成。建议每 5-8 秒轮询一次；传入 `callback_url` 时无需轮询。
</Note>

## 图生视频

基础模式传入 `images` 作为首帧或参考图片。

```bash
curl -X POST https://gogogotoken.com/v1/video/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seedance-2-0",
    "prompt": "基于产品首帧生成一段展示视频，镜头缓慢推进，突出产品材质和屏幕细节",
    "images": ["https://assets.example.com/product-watch.jpg"],
    "seconds": "5",
    "size": "720p"
  }'
```

高级模式通过 `metadata.content[]` 指定首帧、尾帧、参考图/视频/音频，字段与豆包官方 `content` 一致。

```bash
curl -X POST https://gogogotoken.com/v1/video/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seedance-2-0",
    "prompt": "让产品在展示台上缓慢旋转，背景保持简洁，画面稳定且突出品牌质感",
    "seconds": "6",
    "size": "1080p",
    "metadata": {
      "content": [
        {
          "type": "image_url",
          "image_url": { "url": "https://assets.example.com/product-watch.jpg" },
          "role": "first_frame"
        },
        {
          "type": "video_url",
          "video_url": { "url": "https://assets.example.com/reference-motion.mp4" },
          "role": "reference_video"
        }
      ]
    }
  }'
```

使用 [素材管理](/assets) 登记的图片时，将 URL 换为 `asset://asset-xxx`（ID 格式以实际返回为准）：

```json
{
  "type": "image_url",
  "image_url": { "url": "asset://asset-20260627000800-l6jq6" },
  "role": "first_frame"
}
```

### `metadata.content` 中的 `role`

| role | 适用类型 | 说明 |
| --- | --- | --- |
| `first_frame` | `image_url` | 首帧图生视频 |
| `last_frame` | `image_url` | 尾帧（首尾帧生视频） |
| `reference_image` | `image_url` | 参考图片 |
| `reference_video` | `video_url` | 参考视频片段 |
| `reference_audio` | `audio_url` | 参考音频 |

<Note>
  若同时传 `images[]` 与 `metadata.content`，平台以 **`metadata.content` 为准**（`images[]` 不会保留）。
</Note>

## 字段映射（服务端自动完成）

你只需按下方参数提交；平台转换为 ARK 上游 JSON：

| 你提交的字段 | 上游 ARK 字段 | 说明 |
| --- | --- | --- |
| `prompt` | `content[]` 中 `type: "text"` | 必填 |
| `images[]` | `content[]` 中 `type: "image_url"` | 简单图生，不带 `role` |
| `metadata.content[]` | `content[]` | 多模态；含 `role` 时与官方一致 |
| `seconds` / `duration` | `duration` | `seconds` 优先；也支持 `-1`（智能时长）。**2.5** 合法范围为 `4–30` 或 `-1` |
| `size` / `metadata.resolution` | `resolution` | 官方枚举；`metadata.resolution` 优先；不支持像素串。**2.5** 支持 `480p`/`720p`/`1080p`（不含 `4k`） |
| `metadata.ratio` | `ratio` | 如 `16:9`、`9:16`、`adaptive`（首尾帧/编辑/延长建议 `adaptive`） |
| `metadata.output_format` | `output_format` | **2.5**：`mp4`（默认）/ `mov` |
| `metadata.omni_reference_task_type` | `omni_reference_task_type` | **2.5**：`auto` / `reference` / `edit` / `extend`，原样透传 |
| `metadata.generate_audio` | `generate_audio` | 是否生成音频 |
| `metadata.return_last_frame` | `return_last_frame` | 是否返回尾帧 |
| `callback_url` | `callback_url` | 回调通知地址，原样透传 |

## 回调通知（callback_url，免轮询）

提交任务时传入 `callback_url`，任务状态变化（排队 → 运行 → 成功/失败）时上游会主动向该地址 POST 推送任务结果，无需轮询。回调请求体的结构与 [任务查询](/video-tasks) 接口的返回一致（含 `id`、`status`、`content.video_url`、`usage` 等字段），与豆包官方行为对齐。

```bash
curl -X POST https://gogogotoken.com/v1/video/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seedance-2-0-fast",
    "prompt": "一款智能手表在白色展示台上缓慢旋转，柔和棚拍光线，镜头平稳推进",
    "seconds": "5",
    "size": "480p",
    "callback_url": "https://your-server.com/callback"
  }'
```

<Note>
  - 回调地址必须公网可达，并正常返回 2xx 响应。
  - 回调由上游直接发送到你的服务器，不经过平台转发；推送体中的 `id` 是上游任务 ID（`cgt-` 前缀），与本接口提交响应中的 `task_id` 是同一任务。如需校验真伪，可用提交响应的 `task_id` 调 [任务查询](/video-tasks) 交叉核对状态。
  - 回调与轮询可以混用，互不影响。
</Note>

## 提交响应

```json
{
  "id": "task_1234567890",
  "task_id": "task_1234567890",
  "object": "video",
  "model": "doubao-seedance-2-0-fast",
  "status": "queued",
  "progress": 0
}
```

请同时保存响应头中的 `X-Oneapi-Request-Id`（网关本次请求 ID）。若客户端超时未读到 body，可用该值做 [按 request_id 找回](/video-tasks#lookup-by-request-id)。

## 幂等提交（推荐） {#idempotency}

客户端网络抖动或超时重试时，同一业务单号可能多次 POST。请在请求头携带稳定业务键：

| 请求头 | 说明 |
|---|---|
| `Idempotency-Key` | 推荐。同用户、同键在约 **24 小时**内再次提交，直接返回**原任务**（不会再次调用上游、不会重复预扣） |
| `X-Idempotency-Key` | 与上等价的别名 |

重放成功时响应头含：

- `X-Idempotency-Replayed: true`
- `X-Idempotency-Original-Request-Id`：首次创建时的网关 request id（若有）

<Warning>
  仅**创建成功并已落库 task_id** 的请求可被重放或找回。无 `task_id` 的失败响应不要当成排队成功；换键重试前请确认业务是否应新建任务。
</Warning>

## 参数说明

<ParamField header="Authorization" type="string" required>
  API Key 鉴权信息，格式为 `Bearer YOUR_API_KEY`。
</ParamField>

<ParamField header="Content-Type" type="string" required>
  固定为 `application/json`。
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  可选。客户端幂等键；亦可用 `X-Idempotency-Key`。同用户同键约 24 小时内重放原 `task_id`，不重复扣费。详见上文「幂等提交」。
</ParamField>

<ParamField body="model" type="string" required default="doubao-seedance-2-0-fast">
  视频模型 ID。Token 计费：`doubao-seedance-2-5`、`doubao-seedance-2-0`、`doubao-seedance-2-0-fast`、`doubao-seedance-2-0-mini`（fast/mini 不支持 1080p；2.5 支持到 1080p、不支持 4k）。
</ParamField>

<ParamField body="prompt" type="string" required default="一款智能手表在白色展示台上缓慢旋转，柔和棚拍光线，镜头平稳推进">
  视频描述文本。
</ParamField>

<ParamField body="seconds" type="string" default="5">
  视频时长（秒），传字符串如 `"5"`。优先于顶层 `duration`。也可传 `"-1"` 智能时长。**2.5** 为 `4–30` 或 `-1`。
</ParamField>

<ParamField body="duration" type="number">
  时长整数，兼容 OpenAI Video 客户端。若同时传 `seconds`，以 `seconds` 为准；支持 `-1`。
</ParamField>

<ParamField body="size" type="string" default="720p">
  官方分辨率枚举。`doubao-seedance-2-0` 支持到 `4k`；`doubao-seedance-2-5` 支持 `480p` / `720p` / `1080p`；fast / mini 仅 `480p`/`720p`。与 `metadata.resolution` 等价；不支持像素串。
</ParamField>

<ParamField body="images" type="string[]">
  公网图片 URL 列表，用于简单图生视频。多模态或需指定首帧/参考角色时，请使用 `metadata.content`。
</ParamField>

<ParamField body="callback_url" type="string">
  回调通知地址。传入后任务状态变化时上游主动向该地址 POST 推送结果，免轮询；详见上文「回调通知」。
</ParamField>

<ParamField body="metadata" type="object">
  扩展参数，字段名与上游 ARK 一致：`content`、`resolution`、`ratio`、`output_format`（2.5）、`generate_audio`、`return_last_frame`、`seed` 等。
</ParamField>

<ParamField body="metadata.resolution" type="string">
  输出分辨率，优先级高于 `size`。2.5 支持 `480p` / `720p` / `1080p`（不含 `4k`）。
</ParamField>

<ParamField body="metadata.ratio" type="string">
  宽高比，如 `16:9`、`9:16`、`adaptive`。首尾帧 / 编辑 / 延长任务建议 `adaptive`。
</ParamField>

<ParamField body="metadata.output_format" type="string">
  **仅 Seedance 2.5**：输出封装 `mp4`（默认）或 `mov`。
</ParamField>

<ParamField body="metadata.omni_reference_task_type" type="string">
  **仅 Seedance 2.5**：全模态参考任务的子类型引导，可选 `auto`（默认，按素材+提示词自动判定）、`reference`（参考生视频，`ratio`/`duration` 无特殊限制）、`edit`（视频编辑，要求 `content` 含 `reference_video`（或裸 `video_url`）、`ratio=adaptive`、`duration=-1`）、`extend`（视频延长，要求 `content` 含 `reference_video`（或裸 `video_url`）、`ratio=adaptive`）。显式指定可在提交时前置校验参数，减少任务创建后的异步报错（`InvalidParameter.TaskTypeConstraint`）。
</ParamField>

<ParamField body="metadata.content" type="object[]">
  多模态输入数组。每项含 `type`（`image_url` / `video_url` / `audio_url`）、对应 URL 对象，以及可选 `role`（见上文 role 表）。2.5 素材上限约图 ≤30 / 视频 ≤10 / 音频 ≤10（合计 ≤50）。
</ParamField>
